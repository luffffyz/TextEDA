# Review of mcu-board (schematic), round 1

Target `board:mcu-board`, artifact the schematic (`design/sch/mcu-board.teda`). Roles: hardware, pin-audit, librarian. Notes are open: no decision yet. The circular configuration is [ADR-0033](../../../../docs/adr/0033-review-records-and-attribution.md); the method is [role-reviews.md](../../../../docs/guides/role-reviews.md).

- hardware (2026-10-23): `current V3V3 300mA` (`design/sch/mcu-board.teda:63`) is also the LDO's own rating — the component file describes a 300 mA part (`assets/components/regulators/tps7a2033pdbvr.teda:3`) — so the design has no current margin. Dissipation is the sharper problem: at the maximum input the part drops 5.15 V − 3.3 V = 1.85 V, so 0.56 W at the declared 300 mA (`charger-buck.teda:34` gives `VOUT 4.85V..5.15V` as the input range), and 0.47 W at the minimum input. A SOT-23-5 has an Rθja on the order of 200 °C/W (confirm from the TPS7A20 datasheet, SBVS348H); at that figure and the project's 40 °C ambient (`project.toml`, `[compliance] operating_temp`) the junction is far past the limit. Either 300 mA is not a real maximum or the package has to be justified. Settled by: the actual load current, or a thermal calculation in `docs/`.
- hardware (2026-10-23): `VDDA` and `VREF+` sit on the same net as the digital rail with no series element (`mcu-board.teda:46-48`). If ADC accuracy matters, decide the filtering; if it does not, say so. Nothing in the project states either, so the next reader cannot tell a decision from an oversight. Settled by: a note on the net's purpose, or a filter element.
- hardware (2026-10-23): `VIN_5V` declares a voltage range but no current (`mcu-board.teda:61`), while the rail that feeds it is constrained to 3 A (`charger-buck.teda:36`). A constraint states what the design expects; only one side of this link states anything. Settled by: a `current VIN_5V` line, or an explicit statement that the LDO's own limit bounds it.
- pin-audit (2026-10-23): 78 of U1's 100 pins are unconnected (`texteda check --json`, `net.pin-unassigned`). None of them carries a boot, strap, debug or clock role: `BOOT0` (94) is pulled low by R2, `NRST` (14) has R1/C13/SW1, `OSC_IN`/`OSC_OUT` (12/13) have Y1, `PA13`/`PA14` (72/76) carry `SWDIO`/`SWCLK`, and pin 73 is declared `no_connect` in the component. One open question: `PB2` (37) is unconnected — confirm from the CH32V307 datasheet that PB2 has no boot-mode role on this part. Settled by: one line in the review of the datasheet, or a pull-down on PB2.
- pin-audit (2026-10-23): `SWCLK` and `SWDIO` are single-member nets carried only by a board port (`mcu-board.teda:44-45`, `:56-57`). That is legal — `spec/teda.md` §11 rule 4 exempts nets that reach a port — but debug access therefore rests on a connector that has no library part yet; the intent is recorded in a comment (`:6`), not in the design. Settled by: the connector part landing in the library, or an explicit acceptance of the risk.
- pin-audit (2026-10-23): the comment at `mcu-board.teda:7` says ERC warns about single-member nets. It does not: `texteda check` on this project emits zero single-member warnings, and the rule that exempts them is deliberate (`packages/core/src/erc/connectivity.ts`). The comment is stale and will be read as evidence of a known defect that does not exist. Settled by: deleting the sentence.  
  → addressed 2026-10-23: the sentence is gone (`design/sch/mcu-board.teda:6-7` now records only why the debug lines exist).
- librarian (2026-10-23): `tps7a2033pdbvr` has no `ratings` section, so nothing can compare the board's 300 mA against the part; `tps5430ddar` does carry `rated_current current 3A` ([ADR-0039](../../../../docs/adr/0039-a-part-states-its-own-ratings.md)). Without the rating the first note is not checkable by tooling, only by a reader. Settled by: adding the regulator's rated current (and its voltage limit) to the component file.  
  → addressed 2026-10-23: `ratings` added with `rated_current current 300mA` — the number the file's own comment states; the **voltage** limit is still missing, because the file cites no value and inventing one is worse than the gap. Adding a rating does not enforce anything yet: constraint-vs-rating comparison is `docs/backlog.md` F42.
