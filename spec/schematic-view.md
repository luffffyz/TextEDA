# `view` 描述规范（草案）

状态：草案。决策与取舍见 `docs/adr/view/0134-the-view-layer-is-a-drawing.md`（视图层）与 `docs/adr/schematic/0111-one-flat-schematic-per-board.md`（板只有一份原理图文件，绘制划分是打印页）；跨描述通用的词法、单位、版本、canonical 规则见 `teda.md` §3–§5、§10、§12。

本文件是 `teda.md` 的分描述补充：`.teda` 语言的共用规则在 `teda.md`，`view` 这一类描述的具体段定义在这里。

**语言版本**：所有 `.teda` 文件写的是**同一个语言版本号**（当前 `0.9.1`，见 `teda.md` §13.1）。`view` 的下界是 `0.7`：0.6 引入打印页，0.7 起视图里的 id 从"页内局部名"改为"板级名"（`docs/adr/schematic/0111-one-flat-schematic-per-board.md` decision 4），所以 0.6 的视图文件不再被接受（接受规则见 `teda.md` §13.3）。

---

## 0. 定位

`view` 描述表达**一块板的一个"打印页"的"画"**：符号摆在哪、走线怎么走、标签与板端口在哪。

它是原理图逻辑（S0）与渲染器之间的那一层，也就是 `AGENTS.md` §3 分层表里的 **S1**。四条底线（`AGENTS.md` §2、[ADR-0134](../docs/adr/view/0134-the-view-layer-is-a-drawing.md) decision 1 6）：

1. **视图不是第二个真源**。引脚电气类型、net 成员、器件身份都在板文件（`schematic`）里；`view` 只按同样的身份键（`instance_id` / `pin_number` / `net_id`）**引用**它们，不复述。视图与逻辑不一致是缺陷，要报出来。
2. **渲染器只画不摆**。视图里没有坐标，就没有图；渲染器不会替人排版。理由：自动排版每次渲染结果都不同，人无法把重叠的标签挪开，`AGENTS.md` §6 的可读性检查（文字重叠、线压引脚、标签碰撞、越界、连线穿过符号）也就检查不出任何东西。
3. **视图可丢弃、可重画**。它是 S1 层，`AGENTS.md` §3 明确标为"可以自由、可以丢弃"。
4. **视图不改变连通性**。`view` 里的 net 只是引用逻辑层的 net id；它既不新增连接，也不删除连接。连通性由 S0 决定（`AGENTS.md` §2 第 2 条）。

### 0.1 视图用哪一套引脚引用

视图**只写引脚编号**（`U1.5`；层次落地后是 `M1.U1.5`），不写引脚名（`U1.PA0`）、不写多单元简写（`U1.2.OUT`）。

理由：板文件里的引脚引用在**编译时**就被解析成编号形式（IR 里的 net 成员一律是编号，见 `teda.md` §4.5、§12 规则 9）。视图如果允许名字形式，视图与板文件就得各自解析一次名字，两边解析结果还可能不一致（歧义、找不到）。统一成编号形式后，"视图与逻辑对不对得上"就是**同一批字符串的直接比对**，不需要任何解析器在场。

代价是写视图的人得知道编号——这本来就是画图工具该知道的事。

### 0.2 与板文件的关系：打印页

`view` 是**一块板的一个打印页**：板的文件是 `design/sch/<board_id>.teda`（`schematic`），打印页是 `views/<board_id>/<page_id>.view.teda`（`view`）。

| | 板文件 | 打印页 |
|---|---|---|
| 文件 | `design/sch/<board_id>.teda` | `views/<board_id>/<page_id>.view.teda` |
| 描述类型 | `schematic` | `view` |
| 名字空间 | 板级（instance_id、net_id 在板内唯一） | **同一套板级名** |

所以视图里写 `U1.5`、`GND`，指的是**板上**的 U1 的 5 号脚、**板上**的 GND net——与板文件里的字符串逐字相同，没有第二套名字要解析。

**视图用的是板的身份语言，不是它的一部分**：板级 `instance_id`、`net_id` 是什么形状，视图里就是什么形状。当前版本的视图仍按**显示名**引用实例（`U1`、`M1.U1`）；实例的稳定 `uid`（[ADR-0109](../docs/adr/project/0109-instance-identity-is-a-uid.md)）是板级记录的字段，view/pcb 的引用重键不在本版。将来模块层次落地后，模块实例的 id 是 `M1.U1`、模块内部 net 是 `M1.VCC`，视图照样直接写这些名字（引脚引用是 `M1.U1.5`）——因为视图只**引用**身份，不定义身份。视图不认识的写法（比如两个点的 `A.B.C`）在解析期就报错。

打印页是**绘制与打印的划分单元**，不是逻辑的划分单元：画不下、评审想分块看，就多写一个打印页；逻辑始终只有一份。**没有打印页是合法状态**：板仍然可校验、可导网表，只是不可画。评审界面要如实报"此板无打印页"，不能自己排一张。

一个板可以有多个打印页（`charger-power`、`buck-5v`），每个打印页画板上的一部分器件；各打印页画到的 net 与端口都是**板级**的，重名不存在。

决策见 `docs/adr/schematic/0111-one-flat-schematic-per-board.md`。

## 1. 文件头

```
version 0.9.1
view main
```

- 版本行、类型行规则同 `teda.md` §5。
- 文件名必须等于类型行里的 id（去掉 `.view` 后缀）：`views/<board_id>/<page_id>.view.teda` ↔ `view <page_id>`。`.view` 后缀是类型标记。
- 板 id 不写进文件，由目录 `views/<board_id>/` 决定。
- `page_id` 是**打印页**的名字（不是逻辑划分单元）：同一块板的打印页 id 互不相同。

## 2. 标量

标量在第一个段之前，值为行尾剩余文本（`teda.md` §4.4）。

| 键 | 必填 | 说明 |
|---|---|---|
| `sheet` | 否 | 图幅：`<宽> <高>`（mm）。缺省 `297 210`（A4 横向）。 |

顺序无关，canonical form 固定为 `sheet` 在最前。

### 2.1 坐标系

- 单位 **mm**，分辨率 **0.01 mm**（2026-10-25 起；此前是 0.1 mm）。
  为什么必须细到这个量级：走线**只能走 90 度**（§5），而一条离开引脚的线必须先在**引脚自己的那一行或那一列**上，再拐弯；引脚的偏置是 1.27 mm（0.05 in）的整数倍，0.1 mm 网格表达不了 1.27（12.7 格），于是"正交出线"在看到第一根引脚时就不可能。0.01 mm 下 1.27 mm 正好是 127 格，任何引脚落点都能被折点对齐。超出网格仍报 `value.length-invalid`。
- 原点 = **图幅的左上角**；**+x 向右，+y 向下**（与 SVG 的坐标系一致，渲染器不需要翻转）。
- 旋转角度单位为度，**顺时针为正**，缺省 `0`。
- IR 里长度一律是整数纳米（`_nm`）、角度是整数毫度（`_mdeg`），见 `AGENTS.md` §2 第 18 条与 `docs/adr/ir/0105-ir-shards-and-hashes.md` decision 7。

## 4. `place` 段

```
place
  U1    40.0  30.0  0
  C1    20.0  30.0  90
  U2    80.0  30.0  0   unit=2
```

列：`<instance_id> <x> <y> [<rot>] [key=value …]`。

| 列 | 说明 |
|---|---|
| `instance_id` | 板级实例 id（`U1`；模块层次落地后可以是 `M1.U1`），必须在板文件 `design/sch/<board_id>.teda` 的 `instances` 段里存在 |
| `x` `y` | 符号**原点**在图幅坐标系里的位置（mm） |
| `rot` | 符号旋转（度，顺时针为正），缺省 `0`。v0.1 只支持直角旋转：必须是 0/90/180/270，否则报 `value.angle-invalid` |

可选尾列（`key=value`，顺序任意，多余的键报错）：

| 键 | 说明 |
|---|---|
| `unit` | 多单元器件画哪一个单元（`1` 起）；缺省 `1`。取值必须 ≤ 该器件的单元数 |

- 符号画成什么样**不在视图里**：由 `component.symbol` → 符号库决定，渲染器自己去查。视图只说"这个实例摆在哪儿、朝哪儿"。
- 引脚的连接点坐标 = 符号原点 + 旋转后的引脚偏移（符号的几何事实，见 `spec/symbol.md`）。因此**符号改了引脚位置，视图里的线自动跟着走**，视图不需要跟着改。
- 一个打印页只摆它要画的实例；板上的其它实例不出现在这个打印页里（不是错误）。

## 5. `wire` 段

```
wire
  VDD   U1.5  C1.1  35.0 25.0
  GND   C1.2  U2.4  15.0 25.0  15.0 12.0
```

列：`<net> <from_pin> <to_pin> [<bend_x> <bend_y> …]`。

| 列 | 说明 |
|---|---|
| `net` | 板级 net id，必须在板文件的 `nets` 段里存在 |
| `from_pin` | 起点引脚引用（**编号形式** `U1.5`，模块层次落地后是 `M1.U1.5`，见 §0.1） |
| `to_pin` | 终点引脚引用（编号形式） |
| `bend_x` `bend_y` | 折点坐标（mm），可为零个或多个，按顺序经过 |

- 走线的几何 = 起点引脚连接点 → 依次经过各折点 → 终点引脚连接点。**没有折点就是直线**。
- 折点是唯一的"自由坐标"：引脚端点用**引脚引用**而不是坐标，就是为了让视图不复制符号几何（引脚挪了，线自动跟上）。
- **一条线一个 net**：同一 net 可以有多条 `wire` 行（分叉、绕行都靠多行表达）。
- 端点引脚必须属于该 net：`from_pin` / `to_pin` 必须在板 `nets` 段里被声明为该 net 的成员。不一致即报错（`view.pin-net-mismatch`）——这是"视图不重复电气事实"的兑现：视图引用了逻辑层的事实，就必须对得上。
- 不支持圆弧，只支持折线（与 `pcb` 的 `trace` 一致）。
- **只走 90 度**：每一段（含从引脚到第一个折点、从最后一个折点到引脚的两段）必须**平行于坐标轴**——要么纯水平，要么纯垂直。斜线不是风格问题：整页都是横平竖直时，唯一那条斜线会被读成引线或注记，而它的两端是两个"关系待猜"的连接。修法永远是局部的：在两端相遇处加一个折点。违反即报 `view.wire-diagonal`（§9.2）。
- **走线不得穿过引脚连接点，也不得穿过引脚从连接点到符号本体的那段笔画**：引脚是连接点，线从它中间穿过而不在这里结束，读者会读成一个没有圆点的连接；线横穿引脚的短笔画时，读者也分不清哪一段是引脚、哪一段是走线。连接点测试在该引脚就是这条走线的端点时豁免（线本来就结束在这里），**笔画测试不豁免**——从错误的方向接近引脚，仍会跨过读者看得见的那段引脚。修法永远是局部的：在该引脚处把线拆成两条 `wire` 行，或绕开它。违反即报 `view.wire-crosses-pin`（§9.2）。

### 5.1 连接点：画出来的，不写下来的

同一条 net 的走线在**三条或更多条臂**会合处画一个实心圆点（直径 0.9144mm，KiCad 的默认值）。这条规则完全由几何导出，**视图里没有连接点这一项**：

- 一条走线**结束**在该点是**一条臂**，**穿过**该点是**两条臂**；**引脚连接点本身也算一条臂**。臂数 ≥ 3 才画点：一根线接到引脚是 2（线 + 引脚），不画；两根线接到同一引脚是 3，画点。两条走线的拐角（∟）是 2，不画。
- 臂数按**不同的方向**数，不按 `wire` 行数：两行沿同一条线重叠，读者只看到一条线，只算一条臂。否则同一引脚上的两条重合走线会让“只连一根线”的引脚长出圆点。
- 臂数**按 net 分别数**：不同 net 的两条线碰在一起、或交叉穿过，都不画点。引脚只属于一个 net；别的 net 的走线从引脚上穿过是 `view.wire-crosses-pin` 的事，**不在该引脚画点**——点会声称一个不存在的连接。
- 因此读法只有一条：**有点 = 这里是连接，没点 = 只是画在同一处**。这条读法不需要第二个约定去补充，所以**不用半圆跳线**：不同 net 的两条线可以直接交叉，交叉点没有点，读者就知道它们不相连；绕开只是排版选择，不是规则要求。
- 点的图层是 `junction`，**不进反解投影**（§9.5）：连接点是走线的推论，写进 IR 就多了一个能与走线打架的事实。

## 6. `label` 段

```
label
  VDD   35.0  25.0
  GND   15.0  25.0
```

列：`<net> <x> <y>`。

- 标签画的就是 **net id 本身**，**不允许改写显示文字**。标签若能显示与 net id 不同的东西（比如 net 叫 `VDD`、标签写 `3.3V`），图上就会出现"看起来叫 3.3V 的网络"——人读图时会误判网络名。想要 `3.3V` 这个名字，就把 net 命名为 `3.3V`。
- 标签位置必须落在**该 net 的某条走线上**，或落在**该 net 某个引脚的连接点**上；否则报 `view.label-not-on-net`（**警告**，不是错误：视图是给人看的图，位置偏了要提示，但不该让整张图不可用）。
- 同一个 net 可以有多个标签（例如一页上多处标 `GND`）。

## 7. `port` 段

```
port
  SYS_OUT   280.0  105.0  180
```

列：`<port_id> <x> <y> [<rot>]`。

- `port_id` 必须是**板**的端口，必须在板文件的 `ports` 段里存在（`teda.md` §7.5）。
- 端口符号**不创建连接**，它只是给一个已存在的 net 起个对外的名字。视图里画端口符号，位置必须落在该 net 的走线或引脚连接点上（同 `label`，不一致报 `view.port-not-on-net`，警告）。
- `rot` 单位度、顺时针为正、缺省 `0`。
- 画在哪个打印页上都可以：一个板端口可以在多个打印页里各画一次。

---

## 8. `text` 段

```
text
  12.0  8.0   Rev A — power section
```

列：`<x> <y> <text…>`。

- 第三列起是**行尾剩余文本**（与标量同一约定，`teda.md` §4.4），允许空格。
- 纯注释，不带任何电气含义，不参与任何校验（除了"文字重叠"这类可读性检查）。

## 9. 校验

校验分两层：**文件自身能回答的**（解析器做）与**需要板才能回答的**（板交叉校验做，`packages/core`）。下表最后一列是落地状态。

板交叉校验在 `texteda check` 里跑（[ADR-0137](../docs/adr/process/0137-implementation-stack-and-agent-entry.md) 是校验入口）；`texteda ir` 只把分片写出来，不做交叉校验——视图是附注分片，不参与构建身份（[ADR-0105](../docs/adr/ir/0105-ir-shards-and-hashes.md)）。

| `view.wire-diagonal` | 走线有一段**不平行于坐标轴**（§5）：整页横平竖直，唯一的斜线读不出来它的两端是什么关系 | 已实现（可读性检查，同上） |
| `view.wire-crosses-pin` | 走线穿过某个引脚的连接点（该引脚不是这条走线的端点时），或穿过该引脚从连接点到符号本体的笔画（§5）：读者会把走线读成引脚的一部分，或读成一个没有圆点的连接 | 已实现（可读性检查，同上） |
| `view.text-overlap` | 两段文字互相压住（**相切不算**，必须有重叠面积） | 已实现（可读性检查，同上） |
| `view.label-collision` | 两个标签压在一起（label 与 label 的重叠归这条，其余文字组合归 `view.text-overlap`） | 已实现（可读性检查，同上） |
| `view.text-on-wire` | 走线从文字**中间**穿过：字还在，词读不出来。标签与端口**豁免它自己命名的那个 net**（标签本来就落在自己的线上），符号画的字段（Reference / Value）与自由注释不豁免 | 已实现（可读性检查，同上） |

> **不同 net 的走线交叉不报警**：§5.1 的读法只有一条（有点 = 连接，没点 = 不连接），所以交叉本身不是缺陷；`view.wire-crossing` 已废弃，只为旧报告保留码表行，`check` 不再发出。

> 码表见 `docs/error-codes.md`（由 `packages/ir/src/diagnostics/codes.ts` 生成）。诊断码按"错误的种类"分域，不按发现阶段分（[ADR-0102](../docs/adr/language/0102-diagnostic-error-codes.md)）："引用了不存在的东西"在 `view` 里和在 `sch` 里是同一类错误，所以复用 `ref.*`；"角度不合法"复用 `value.angle-invalid`。`view` 域是本描述引入的新域，授权见 [ADR-0134](../docs/adr/view/0134-the-view-layer-is-a-drawing.md)。
>
> **注册表只登记"已发出"的码**（[ADR-0102](../docs/adr/language/0102-diagnostic-error-codes.md) decision 7：码表是唯一真源，发出即冻结）。本表全部十个码都已发出并登记。
>
> **几何从渲染器来，不从检查器推**。文字宽度、符号本体范围、引脚落点都由 `packages/renderer` 的 `schematicGeometry` 按**实际画法**算出（同一套变换、同一套笔画字体度量），检查器只判断"压没压住""在不在线上"。检查器自己再算一遍就会和读者看到的东西漂移，那正是可读性检查要防的那类错误。
>
> **字段也在几何里**（2026-10-25）：`schematicGeometry` 除了视图自己的三条记录（`label` / `port` / `text`），还给出每个已放置实例的 `fields`——符号画的 Reference / Value 在纸上的框（含旋转，按绘制后的矩形取包围盒）。它们不是视图的记录（作者改不了位置，要改符号），但读者分不清哪个字来自哪个文件，所以检查器两者都读：`view.text-on-wire` 就靠它报出"走线穿过位号"。

### 9.2.1 每条警告带多少

警告是二值的（"在"或"不在"），但**带量**才可修。`--json` 载荷的 `data` 字段因此一律给数字，单位与 IR 一致（纳米）：

| 码 | `data` |
|---|---|
| `view.label-not-on-net` / `view.port-not-on-net` | `page` `net` `kind` `distance_nm`（到该 net 最近走线或引脚的**距离**） |
| `view.label-collision` / `view.text-overlap` | `page` `first` `second` `overlap_area_nm2`（重叠**面积**） |
| `view.text-on-wire` | `page` `net` `kind` `text` `through_nm`（在文字框**内部**的长度）；字段另带 `instance` |
| `view.wire-crosses-symbol` | `page` `net` `instance` `through_nm`（在**本体内部**的长度） |
| `view.wire-diagonal` | `page` `net` `segments`（斜段**条数**）`x_nm` `y_nm`（第一段斜线的起点）`off_axis_nm`（该段偏出轴线的量 = min(abs(dx), abs(dy))） |
| `view.wire-crosses-pin` | `page` `net` `instance` `pin` `x_nm` `y_nm`（引脚连接点）；穿过笔画时另带 `cross_x_nm` `cross_y_nm`（笔画上的穿越点） |
| `view.nets-not-drawn` | `count` + 前十个 net 名 |

同一组数字在人类可读输出里换成 mm / mm²，出现在消息里（"nearest point of the net is 6.8 mm away"）：一个偏 0.1 mm 的标签和一个偏 20 mm 的标签是同一条警告、两种完全不同的修法。

### 9.3 不校验的事

- **视图不参与 ERC**。ERC 在板的逻辑 IR 上跑（`AGENTS.md` §4.2），视图里的线画错了不会让 ERC 变红——那是 `view.*` 诊断的活。
- **视图不改变连通性**。视图里少画一条线，逻辑层照样是那个 net。

### 9.5 可反解（round-trip）

渲染器只读（`AGENTS.md` §2 不变量 3），所以它画的每一页都必须能反解回"这一页说了什么"——`extract(render(ir)) == ir`（不变量 4，[ADR-0135](../docs/adr/view/0135-our-own-reference-renderer.md) decision 5）。

**比的是语义投影，不是 IR 本身**。一张打印页的语义是落在纸面上的东西：图幅大小、引脚连接点与朝向、符号自身的图形、走线折点、标签与注释的文字与位置、端口标签的尖点与朝向，全部在**绝对图纸坐标**里。以下故意不在投影里：

| 不进投影 | 理由 |
|---|---|
| 摆位原点与旋转 | 读者看到的是引脚落在哪，不是原点在哪；原点算错但每个引脚都落在原处的图，不是这张图的缺陷 |
| 线宽、字号、对齐方式 | 外观，不是语义；符号自身的绘制由符号的 round-trip 负责 |
| 端口标签的塔形细节 | 只比尖点与朝向，改标签外形不算失真 |
| "这个引脚属于哪个实例" | 图上没有这条信息；同一符号的两个实例互换位置画出的是同一张图，实例身份靠 `Reference` 文字（也进投影） |

**库里那两个字段是占位符**：符号文件的 `Reference`（`U`）与 `Value`（符号名）只是"这里有个位号、有个值"，图上画的是实例自己——`Reference` 用实例 id，`Value` 用实例的 `value` 列（件没有这一列时用 `mpn`），见 `spec/symbol.md` §2。因此这两段文字的**内容**进投影（两端各自算出来再比），而不是画符号文件里那句占位文本。

**转过的器件，字段文字朝外长**：实例转 90° 或 270° 时，两个字段的锚点被带到本体两侧；文字居中就能互相压住（`220uF` 压在 `M2.C3` 上），所以左侧那位的文字以锚点为**结尾**、右侧那位以锚点为**起点**，两段都朝远离本体的方向排。正放（0° / 180°）时仍是居中对齐——一上一下不会撞。这是参考渲染器的排版选择（文字位置不进投影），不是契约。

**两端独立实现**：视图侧用象限矩阵把符号坐标换到图纸坐标（`schematicProjection`），图纸侧直接读绘制指令（`extractSchematic`），两者不共用变换函数——共用就等于自己验证自己。落在复现性上：同一份 `view` 两次渲染字节相同（§11），反解也相同。

实现：`packages/renderer/src/schematic-extract.ts`；测试：`packages/renderer/test/schematic-roundtrip.test.ts`（四个象限 + 走线端点落在引脚上 + 灵敏度）与 `packages/cli/test/view-roundtrip.test.ts`（参考工程的每一页）。

### 9.4 度量（`texteda view metrics`）

警告之外，一张页的**量**由 `texteda view metrics <工程目录> <board>/<page> [--json]` 给（`packages/core/src/view/metrics.ts`）。它与可读性检查读**同一份几何**（`schematicGeometry`），所以"这条线离那个 net 多远"在两边只有一个答案。

| 量 | 含义 |
|---|---|
| `content` / `content_fill_ppm` | 所有图元的外接框，以及它占图幅的比例（ppm；靠近 1000000 说明画面快撑满） |
| `counts` | 实例 / 标签 / 端口 / 注释 / 走线数，以及本页没画走线的 net 数 |
| `label_min_gap_nm` / `text_min_gap_nm` | 任意两段文字的最小间隙（0 = 相接或压住）；不足两段时缺省 |
| `wire_total_nm` | 走线总长 |
| `wire_crossings` | **不同 net** 的走线互相穿越的次数（同一 net 交叉是汇合，共享端点更不算） |
| `wires_through_bodies` | 穿过非本端点的符号本体的走线条数 |
| `net_texts[].distance_nm` | 每个标签/端口到它所指 net 的距离；`-1` = 该 net 在本页没有任何走线或引脚 |

**为什么不是截图**：像素不能跨渲染比较（抗锯齿、视口、字体），一次截图要过视觉模型、说不出"差 0.2 mm"，也进不了 CI。agent 画图的循环是 `写 → check（对不对）→ view metrics（差多少）→ 改`，SVG 快照留给人的评审——判定要机器给，观感要人给。

### 9.4.1 打印页的命令（`texteda view`）

打印页作用域的命令归在一个名词底下（[ADR-0143](../docs/adr/process/0143-the-agent-surface-is-a-set-of-verbs.md) D6）：

| 命令 | 做什么 |
|---|---|
| `texteda view metrics <工程目录> <board>/<page> [--json]` | §9.4 的量 |
| `texteda view rewire <工程目录> <board>/<page> [--dry-run] [--json]` | 把走线重新锚回引脚（见下） |
| `texteda view render <工程目录> <board>/<page> [--out <文件>] [--json]` | 把这一页画成 SVG 文件（与评审 app 同一渲染器） |

**`view rewire` 做什么**：走线行的端点写的是**引脚引用**，所以符号一动端点就跟着动，而折点留在原地——走线会歪（`view.wire-diagonal`）。`view rewire` 把折点重新算出来：中间的折点坐标不动，两端按引脚现在的位置重算。方向从走线自己读出来：相邻两段不能同向（同向就是一条线），所以端段的轴向由它旁边那一段决定（`packages/core/src/view/reroute.ts` 的 `rerouteWire`）。

**它不是路由器**：不搜索、不绕行、不看符号本体；内部有斜段的走线只**报冲突**（ADR-0141 D6），不重画。

### 10.1 正例

```
version 0.9.1
view main

sheet 297 210

place
  U1    40.0  30.0  0
  C1    20.0  30.0  90
  R1    60.0  30.0  0

wire
  VDD   U1.5  C1.1  35.0 25.0
  VDD   C1.1  R1.1  25.0 25.0  55.0 25.0
  GND   C1.2  R1.2  25.0 35.0  55.0 35.0

label
  VDD   35.0  25.0
  GND   25.0  35.0
```

### 10.2 反例

```
version 0.9.1
view main

wire
  VDD   U1.5  C1.1
```

**错在哪**：`C1` 没有出现在 `place` 段（`view.pin-not-placed`，解析器就会报）；`U1.5` 与 `C1.1` 都没在板的 `nets` 段里声明为 `VDD` 的成员（`view.pin-net-mismatch`，板交叉校验时报）。

**怎么修**：把 `C1` 摆进 `place` 段，并在板的 `nets` 段里声明 `VDD: U1.5 C1.1 R1.1`。

## 11. Canonical form

- 段顺序固定：`place` → `wire` → `label` → `port` → `text`。
- 段内行按**自然序**排序（标识符里的数字段按数值比，`C2` 在 `C10` 前；见 `teda.md` §12 规则 9）。
  - `place` 按 `instance_id` 排；
  - `wire` 按 `(net, from_pin, to_pin)` 排；
  - `label` 按 `(net, x, y)` 排；
  - `port` 按 `port_id` 排；
  - `text` 按 `(x, y, text)` 排。
- 列宽按段内最大值对齐；行宽超过 80 列时**不折行**（`wire` 的折点是成对坐标，拆行会断配对，与 `pcb` 的 `trace` 同理，见 `teda.md` §3 末条）。
- `wire` 的前三列按段内最大值对齐；**折点坐标成对排**（`x y` 组内一个空格、组间两个空格），因为折点拆开就看不出配对。这一条是 `teda.md` §12 规则 3 的例外，理由同 `pcb` 的 `trace`（`spec/pcb.md` §6.2）。
- `place` 的旋转列与 `unit=` 尾列分开对齐（旋转可能缺省，`unit=` 可能没有）。
- `wire` 的折点按经过顺序排列，不排序（顺序有语义）。
- 源文件里同一行的顺序不影响 IR：IR 里的 `points` 保留折点顺序，其余数组按上面的键排序。
- 缺省值在源文件里**可以不写**（`rot` 缺省 0、`unit` 缺省 1、`sheet` 缺省 A4 横向）；IR 里缺省字段一律省略，所以 `rot=0` 与不写旋转是同一个文件。
