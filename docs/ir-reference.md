# IR Contract Reference (v0.7)

> Generated by `packages/ir/scripts/generate.ts` from `schemas/ir/v0.7/`; do not edit by hand.
>
> This table answers only two questions: **what type a field is** and **what its unit is**. Behavioral semantics are defined by `spec/` (the language-wide spec is `spec/teda.md`).
>
> Units are determined by field-name suffixes (ADR-0008 decision 4): `min_uv` is voltage (µV), `max_na` is current (nA), `value_mohm` is impedance (mΩ).

## `common`

- schema: `urn:texteda:ir:0.7:common`
- Scalars, identity patterns and unit conventions shared by all shards. The field-name suffix is the unit: _nm nanometers, _mdeg millidegrees, _mohm milliohms, _uv microvolts, _na nanoamps, _uw microwatts, _mhz millihertz, _mdegc millidegrees Celsius, _ppm parts per million, _uohm microohms, _ff femtofarads, _ph picohenries. Rules: docs/adr/0008-ir-shard-identity-and-hash.md.

## `component`

- schema: `urn:texteda:ir:0.7:component`
- Semantic projection of one .teda component file. Pins must already be materialized in the IR: inline pins are copied verbatim; when `symbol` points to a third-party library that carries pin facts and the file omits `pins`, the parser expands them from the library and `pins_source` records the source. A self-built `symbol` stores only the view, without pin facts (ADR-0012), so a component pointing at a self-built symbol must inline `pins`.

## `manifest`

- schema: `urn:texteda:ir:0.7:manifest`
- Shard manifest and hashes: one sha256 per shard (computed over the canonical JSON bytes) and its classification; the project hash covers the normative shards, the advisory hash the advisory ones (ADR-0023 decision 4, amended 2026-10-22). The hashes are recomputed by rule and not persisted elsewhere. See ADR-0008 decision 5.

A hash identifies a build, not the project's file set: changing an advisory shard changes this hash and leaves the project hash alone. |
| `ir_version` | ir_version | yes | — | IR contract version, currently always 0.7. |
| `note` | note | no | — | Free text; canonical JSON has no comments, this is the substitute. |
